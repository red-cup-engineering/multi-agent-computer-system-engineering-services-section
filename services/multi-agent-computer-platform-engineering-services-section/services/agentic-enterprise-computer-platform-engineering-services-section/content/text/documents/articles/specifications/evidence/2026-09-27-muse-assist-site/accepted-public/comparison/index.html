Assistant references and evidence limits — muse-assist

A dated comparison frame separating supplier descriptions, muse-assist intent, and independent observations.

What this comparison says

muse-assist is this 561 Group project. Meta's Muse is a distinct product and the primary reference that prompted this work. Microsoft Copilot Cowork and Google Gemini Spark are included as additional supplier-description references. The sources below were reviewed on 2026-09-27. They describe products; they are not independent measurements or endorsements. No live access, common task run, or whole-platform comparison has been performed.

The comparison dimensions are useful effects to assess, not feature scores. Statements about the other products below summarize their suppliers' published descriptions. A source that does not establish a behavior is not evidence that the product lacks it.

Continuing work

Meta describes Muse as able to handle concurrent tasks and continue work on schedules or events (How We Designed Muse). Google describes Spark as providing ongoing personal assistance and tasks through connected Workspace applications (Gemini Spark). Microsoft's Cowork guide describes task execution across Microsoft 365 applications (Use Copilot Cowork). These descriptions do not establish equivalent persistence behavior across the products. muse-assist intends to carry authorized work across interruptions; that end-to-end behavior has not been demonstrated.

Connected actions

Meta's description includes computer and browser use; Microsoft's guide discusses work across documents, mail, and meetings; Google's description discusses connected Workspace applications. These are supplier-described integration surfaces, not results from a shared task or verification of receiving-system outcomes. No muse-assist integration set or end-to-end connected action is claimed here.

Context and correction

Meta describes editable memory. The cited Microsoft and Google references do not establish a directly comparable context-editing and correction path. This is a limit of the cited evidence, not a claim that those products lack such a path. muse-assist intends to preserve relevant context, provenance, and human corrections; this remains a design goal without an accepted integrated demonstration.

Usable artifacts

Meta's description includes usable artifacts. Microsoft's guide names work with documents and other Microsoft 365 resources. Those supplier descriptions do not report an independently assessed artifact or its acceptance by a receiving person or system. This project has not measured artifact usefulness or acceptance.

Human authority and security boundaries

Microsoft's Cowork guide describes approval before changes to shared systems. Meta separately describes an approach that places execution and credential/permission boundaries outside model control (Meta security and safety account). These remain supplier statements; this page reports no independent security review. The cited Google Spark description does not establish an equivalent authorization model, which is not evidence of its absence. muse-assist intends to keep consequential actions under attributable human authority; its enforcement path is not accepted or demonstrated.

Outcomes where work is received

None of these sources supplies a common independent measure of whether work was accepted or had the intended effect in the receiving system. No comparative receiving-outcome results are available. Missing access and results limit what can be concluded; they do not indicate a competitor failure or a muse-assist advantage.
