## Useful effect and removed mechanisms

MetroPlat presents the actions installed in a particular node and dispatches an admitted request to that same action contract. Keep the existing family constructors, generated family descriptions, instance-selected sources and shared typed dispatch. Remove the global generated callable-catalog and MCP-tool snapshots, declaration-time Codex recovery, and generation's dependence on its own previous output or a journal's current authority state. Constructor purity must be observed for each family; the directory or factory name does not establish it.

This is a refinement of L-C08's matching discovery/execution requirement and operation-admission L-OA01–L-OA07. It changes F-C01/F-OA03's provisional instruction to preserve three generated outputs: only the family-declaration artifact has an independent generation role. Their governing fabrication orders must be amended with this derivation before realization. This document does not authorize bypassing the existing promotion condition while those orders remain unchanged.

## L-G01 — One declaration source, one generated projection

Use the operation declarations already constructed by each owning family as the authoritative declaration source. Do not copy the operation specifications to a new manually maintained registry, build a parallel catalog, extract arbitrary JavaScript with regular expressions, or infer new grants. scripts/generate-operation-family-descriptors.mjs retains its current module selection and existing generate/check commands, but projects only src/generated/operation-family-descriptors.mjs using operationDescriptor.

The generator must never import catalog.mjs or either retired catalog/tool output, directly or through its effective generation closure. It must not call assembleDefaultServiceMcp, readProgramContractEvidence, capability settlement, permission preparation or application runtime startup. Generated family data describes declarations; it neither designates a callable operation nor grants a participant authority. Any old family descriptors may be absent or deliberately corrupted without changing newly generated bytes. A changed source declaration must affect the newly generated result in that same run.

The current module list selects family factories; preserve it in the generator instead of adding another list. Runtime loading keeps its corresponding owner selection. Declaration metadata and execution remain checked by L-OA05. A family whose declaration needs configuration must receive explicit bounded declaration input rather than reading the operating environment.

## L-G02 — Constructor purity and explicit inert binding

Do not call defaultFilesystemBinding for generation. Supply an explicit immutable declaration binding with fixed non-operational data, session, memory and workspace root labels. Every effectful filesystem, resolution, time or external port exposed by the binding refuses if called, with a diagnostic identifying the family and requested port. No port returns an invented successful observation. Closures may retain these ports without invoking them; declaration generation never invokes an operation body. No provider credentials, working journals, host homes or agency data are mounted into its execution environment. The fixed roots explicitly include `agencyRoot`. The current offices `agencyRootOf(binding)` checks that field before consulting ambient configuration or searching checkout ancestors for .git; declaration construction must use the explicit inert agency root and never enter either fallback.

Preserve the existing schema/compiler and operation implementations in the generation dependency closure. Isolate generation with network disabled and bind only its exact source/runtime dependencies plus its output directory. Observe actual reads/process/network activity as well as calls through the binding; a factory importing node:fs directly does not become pure merely because binding-port counts are zero. Allowed source/module-loader reads are distinguished from operational reads. Time, randomness, ambient configuration and filesystem order must not determine descriptor content.

Validate each currently selected family's construction under this boundary. If a constructor uses an operating port eagerly, preserve its underlying effect at explicit runtime activation or action execution and specify that particular move before source derivation. Do not return an empty family, omit a failed family, substitute a successful grant, or add a universal declaration framework to make generation complete. Bind the complete effective import closure; the smaller operation-admission observation closure is insufficient.

A successful whole-generation observation must cover every selected family, produce the same bytes in two independently rooted inert environments, and show no runtime recovery or operating data access. This is a generation observation, not evidence that arbitrary runtime factories can receive personal capabilities safely; L-C10 remains governing for personal loading.

## L-G03 — Explicit Codex runtime activation

The existing loadOperationFamily Codex branch starts recoverCodexTasks while constructing descriptors and supplies a `ready` promise which codexTaskOperations currently ignores. The current code therefore does not guarantee recovery-before-execution. Preserve recovery as a useful runtime effect and close that race explicitly; do not describe it as already working.

Export `activateCodexTaskFamily(binding, {environment = process.env} = {})` from the existing operation-family-loaders.mjs. It returns the recovery promise memoized by the exact normalized dataRoot, including failure. It constructs the same Codex options as family loading through one shared local option constructor: dataRoot, configured/default workspace, character, model and executable. No second maintained options table or new lifecycle service is needed. Resolve the workspace lazily: a supplied METROPLAT_CODEX_WORKSPACE is already sufficient and must not cause an agency-root lookup. Without it, preserve the existing path.dirname(agencyRootOf(binding)) fallback for both construction and activation; path.dirname(binding.dataRoot) is not an equivalent default. Process configuration is stable for a host lifetime; callers for the same root must share its binding/configuration, not substitute a request-supplied environment. A rejected promise cannot be evicted to restart recovery during later invocations.

`loadOperationFamily` accepts the trusted `context.environment` for this construction, with existing process environment as the runtime compatibility default. The descriptor generator supplies an explicit immutable empty environment and fixed inert roots. Constructing the family does not call activation; it passes `ready: () => activateCodexTaskFamily(binding, {environment})` to codexTaskOperations. Add `ready` as an optional callback to the latter's existing options. Each task handler awaits it before any task read, start, withdrawal, integration or write. Omission preserves direct non-MetroPlat callers' current behavior; every MetroPlat-loaded family supplies it. A failure prevents the handler's work. Do not start recovery during operation construction, descriptor projection or help/discovery generation.

MCP's existing configured Codex-startup trigger calls this explicit activation export instead of loading the family. It uses the host's actual environment argument, not a separate ambient configuration. Retain startup error observation and once-per-root recovery. An authorized task invocation in CLI, HTTP or MCP reaches the same readiness callback after shared dispatch selects and authorizes its operation, so lazy use does not require duplicating startup orchestration in each transport. Unrelated CLI help/actions do not start Codex recovery. Configured MCP startup can still initiate it without a first task call. Task recovery and personal authority remain separate obligations; no personal handler acquires the Codex process root from this change.

The explicit host environment must also reach lazy family loading. At host construction, snapshot its supplied environment as a trusted immutable record and use that same record for configured startup and the serving surface. Pass it as `environment` to conurbationMcpApex; defaultMcpApex removes this field from filesystem binding options and passes it as a final optional argument to assembleDefaultServiceMcp. Add that final optional environment argument to the existing catalog assembly/source-set/serviceSources path, defaulting to process.env for existing non-host callers, and supply it in loadOperationFamily's context. The same argument is threaded through assembleDefaultService for consistency. Existing positional callers keep their meaning. Do not hide environment propagation in workOptions, assume a supplied environment equals process.env, or depend on startup happening before the first task call. Each root's actual task options and readiness activation must use the same captured host configuration. For conurbations the snapshot is shared configuration, not shared data-root authority or shared recovery state.

## L-G04 — Discovery from the serving instance

openMetroplatMcp must answer tools/list from the same memoized serving surface used by programMcpHandle for calls. Use the existing programMcpToolsWithEndpoints projection with that surface's operations, discovery.programs and discovery.package. Do not concatenate a global static list with installed actions, re-run family construction just for listing, or advertise descriptors whose executable contract is absent from the selected surface.

Keep installedMetroplatFromProcessOptions as the source of the instance identity and its FERN/operationSources selection. Keep separately installed web applications and their authenticated web composition; an application factory is not interchangeable with an operation-family factory. Instance restrictions, personal scoped loading and current authorization still govern actual calls. Discovery is descriptive and cannot grant authority; a later revocation must still prevent use at the existing execution boundary.

For a conurbation, project the actual aggregate surface with its qualified verbs and preserved constituent-owned authorization. Never turn it into an unqualified union or share a root's authority with another root. Discovery and calls use the same selected operation and root mapping.

Initialization may continue to report identity and protocol capabilities without executing an action. An instance with no additional operationSources still serves its assembled built-in operations; discovery must list that exact serving surface and must not invent instance-installed actions. An actually empty serving surface projects to an empty tool list. This condition does not introduce a new host mode for disabling core operations. A surface-construction failure refuses discovery rather than falling back to old global descriptors. Concurrent discovery/call requests share one surface-opening promise, including its failure, and shutdown retains the clock/worker lifetime responsibilities. The sole production caller found, web/serve-instance.mjs, uses handle and close; scripts/metroplat.mjs constructs its own CLI surface. Remove the unused returned induced/options placeholders. Keep the host handle/close interface and its internal memoized open function. No new public asynchronous accessor is needed without a consumer.

## L-G07 — Venue activation belongs to order execution

The isolated whole-generation observation found that Kalshi's operation factory statically imports its order-placement module, which reads content/config/activation.json at module initialization. Source inspection establishes the same dependency in the Polymarket family. These are operating activation records, not declaration schemas. Keep the complete Kalshi and Polymarket action families, all verbs, summaries, descriptions, schemas, effects, reads/writes, order-intent calculations, forecasting and public-market reads. Remove only the static dependency from each owning src/operations.mjs to ./orders.mjs. The existing order-placement operation's handler loads that same module on execution and invokes its existing exported placeOrder with the unchanged input. Preserve its asynchronous result and error propagation. JavaScript module caching retains the module's current process-lifetime activation behavior after first use; do not add another loader cache, activation service or admission route.

Do not change either orders.mjs, the shared createPlaceOrder gate, activation configuration, credential custody, or either venue client. A declaration does not read activation or credentials and does not imply authority to place an order. Actual calls continue through common operation dispatch/authorization and then the existing venue gate. No market order or external request is needed for receiving.

In addition to L-G06, bind the two factory sources and unchanged order-gate sources. Observe generation with both activation files unavailable. In isolated runtime receiving with no credentials/network, separately provide each venue a fixture activation whose orderExecution is disabled: calling its real placement operation must retain the existing activation-refused result with venueWrite:false. A missing activation file must fail when the operation is invoked, while constructing/describing the family still succeeds. The fixture is runtime-only and never mounted into descriptor generation. Preserve these as separate generation and execution observations.

In all four owning operations modules, the eager ENTERPRISE value is consumed only by a runtime settings closure. enterpriseStore construction merely captures a semantic journal root and methods; it does not query or write the journal. Preserve those constructors, operations, schemas, store calls, current-setting selection and authority paths. Remove the eager constitution read by replacing that value with a module-local synchronous accessor called only at its existing settingValues argument. On the first use, read the same section-relative enterprise record and apply the same JSON parser and enterpriseOf validation. Retain that first result or thrown error for the module lifetime; later calls return the identical enterprise or throw the identical error without rereading. This retains the existing module-lifetime snapshot/failure behavior, moving its start to operational use. It does not grant authority, invent settings, consult another enterprise or migrate the enterprise store.

Land and US representation discover document choices from the Markdown files bundled under their own content/text/documents/templates directory. Preserve that direct enumeration, sorting, domain enum and description. These exact bundled source files are legitimate generation dependencies. Bind directory membership, regular-file types and content hashes before generation; mount only those source files, with no writable directory or operational agency records. A changed membership or file hash invalidates the receiving input and requires rebinding. Do not replace discovery with a second maintained list. The dependency inventory is a derived receipt, not a product registry.

Independent receiving must construct and describe all four complete families with enterprise records absent, then invoke an actual settings-consuming operation and observe its original missing-file refusal. Separately exercise invalid and valid fixture-only constitutions. Invalid constitution validation must fail only on use and retain the same error without repeated reads. A valid constitution is read once across repeated calls and separate constructors; settings-dependent output must reflect its declared values and subsequent current store settings, rather than fabricated defaults. Actual operation declarations remain identical under these runtime-only record variations. Generation remains isolated from all constitution fixtures and operating state. Retain every earlier generation, host, recovery, venue and Hive receiving obligation.

## L-G11 — Await the constituent authorization decision before requalification

Actual conurbation execution reaches a pre-existing mismatch in mcp-surface: it spreads constituent.apex.authorize's return synchronously. Systems authorizationUnderRules may return a promise, including when the rules judgment is asynchronous. Spreading that promise retains none of the authorization decision's invocation, subject, reading, evidence or ok fields. Dispatch then correctly refuses the malformed decision. Preserve that refusal boundary.

Make the conurbation authorize closure asynchronous and await the owning constituent's actual authorize result before restating its operation reference to the qualified operation reference. Preserve every other resolved decision field exactly, keep the original invocation and constituent action arguments, and retain rejection propagation. The unknown-owner fallback still delegates to aggregate.authorize and may resolve asynchronously. Do not invent a successful decision, merge constituent assertions, rewrite the subject/invocation, relax dispatch validation, or change root ownership. Existing real conurbation receiving must prove own-root execution and both cross-root refusals with no effects. Synchronous authorization also remains supported by await.
