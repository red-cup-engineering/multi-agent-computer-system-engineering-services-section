## Purpose and boundary

This LLD specifies the domain value and fold for the shared effect-successor admission selected by L-E02–L-E04. Each control transition is admitted as the L-J01 `effect-successor` unique command, with the exact predecessor witness in its slot key and causes. The transition validator must resolve and validate referenced evidence under L-W02; reference syntax, a model assertion, a UI status, or a Boolean such as `authorized`, `safeToRetry`, `sent`, or `complete` proves nothing by itself. The admission boundary validates before create-once publication. `created` is a durable journal result; only the live call that receives `created` for a send-permission event gets the transient one-shot dispatch capability in L-E04.

This defines control shapes and transition semantics, not a new journal, task database, scheduler, authorization service, or receiving adapter. The chain binds both personal `PersonalWorkAssignment@1` and genuine institutional allocation variants without converting one into the other. It does not mint grants. The owning journal and current external authority sources remain responsible for resolving referenced facts.

## Closed event envelope

The command `value` has exactly these envelope fields:

```json
{"kind":"metroplat.work.effect-transition","version":1,"effectId":"…","transition":"…","data":{}}
```

`kind` and integer `version` are literals. `effectId` is a nonempty `BoundedId` (1–512 Unicode scalar values) equal to the effect-successor key's `effectId`; it is not caller authority. Every identifier string in this contract uses the same bound unless an inherited contract is stricter. Each `Ref[]` evidence/revision list is unique and sorted by canonical reference bytes. `transition` is one of the variants below. `data` has exactly that variant's listed fields. No extensions, missing fields, unknown enum values, implicit nulls, duplicate references, or additional properties are accepted. All references are exact L-W02 references; reference resolution checks journal, subject, event, payload, expected kind, access, and retained bytes. `command.key.journal` must equal the configured owner journal. Its predecessor is null only for `effect-open`; otherwise it is the exact prior admitted control-transition witness and appears in `command.causes`. It is the latest control head, not an ordinary observation or receiving assessment.

The command's `subject` is deployment-bound to the effect owner/context under the journal's existing subject rules. `command.causes` is exactly the unique, ordinal-sorted projection of causal `Ref.event` strings: it includes the predecessor event and every direct causal event named by the transition. `artifactRefs` retains the necessary immutable bodies and uses unique references sorted by canonical reference bytes. Evidence-reference arrays in `data` use that same canonical-reference-byte order. The validator refuses missing, surplus, unavailable, forbidden, wrong-kind, wrong-digest, or noncanonical references. L-J04 generates the authenticated actor and admission time; neither is copied from model text or a payload field.

`Ref` is the exact L-W02 object `{journal,subject,event,payload}` and must resolve/authenticate as the expected immutable source. `Digest` is the existing `addressArtifact(canonicalProposal).ref` and must equal the referenced proposal `Ref.payload`; it is not a second digest scheme or a caller-supplied attestation. References are not authority merely because they resolve; each domain validator checks source kind, owner/scope, principal, validity, correspondence, and applicable authority under its governing contract.

## Closed transition variants

| `transition` | Exact `data` fields | Validation effect |
|---|---|---|
| `effect-open` | `{intentRef: Ref, assignmentKind: "personal"|"institutional", assignmentRef: Ref, proposalRef: Ref, proposalDigest: Digest}` | Initial predecessor only. Resolve the intent, exact proposal, and assignment variant. Verify same owner/context and receiving goal; for personal work verify the exact `PersonalWorkAssignment@1` owner/provider/receiver/scope and provider admission; for institutional work verify actual allocation/delegation. Preserve provider ≠ independent receiver. Does not prove current execution authority. |
| `proposal-revised` | `{priorProposalRef: Ref, priorProposalDigest: Digest, proposalRef: Ref, proposalDigest: Digest, revisionCauseRefs: Ref[], assignmentRef: Ref}` | From `effect-open`, another `proposal-revised`, or `pre-send-refused`; it may follow `retry-eligible` only when that gate is `authoritative-reconciliation` and its resolved evidence proves the prior attempt had no receiving effect and its sender/queued transport cannot later commit. It cannot follow an idempotency-only gate. Verify proposal revision/cause correspondence, same effect and receiving condition, same authority variant, and valid assignment revision. Retain prior proposal. Any semantic change invalidates earlier decisions and any idempotency recovery gate keyed to the prior bytes; this event grants no approval. After permission, changed bytes are admissible only by the authoritative-reconciliation/no-effect route above, never by assuming a prior idempotency key covers new bytes. The `assignmentRef` may advance only within the established personal/institutional variant and must resolve as a real revision; it cannot switch a personal effect into an office allocation or vice versa. |
| `attempt-prepared` | `{attemptId: BoundedId, proposalRef: Ref, proposalDigest: Digest, assignmentRef: Ref, adapterContractRef: Ref, priorAttemptRef: Ref|null, recoveryGateRef: Ref|null}` | From `effect-open`, `proposal-revised`, `pre-send-refused`, or `retry-eligible` only. `priorAttemptRef` is null iff there has never been an earlier prepared attempt; otherwise it identifies the latest earlier prepared attempt. `recoveryGateRef` is null iff no earlier attempt ever obtained send permission. Otherwise it identifies the currently valid `retry-eligible` gate for the most recent permitted attempt, which can differ from priorAttemptRef when an intervening preparation was refused before permission. A pre-permission refusal cannot erase that earlier recovery obligation; re-evaluate the retained gate against all applicable observations and current adapter conditions. No older permission may be skipped while unresolved. The first attempt has both fields null. `attemptId` is a fresh owner-scoped `BoundedId`. Resolve the exact proposal, digest, current assignment revision, and operator-admitted adapter contract; bind operation, typed bytes, destination/recipient, disclosure, limits and receiver predicate from that proposal. No alternative proposal bytes can share this attempt. |
| `send-permitted` | `{preparedRef: Ref, attemptId: BoundedId, proposalRef: Ref, proposalDigest: Digest, assignmentRef: Ref, adapterContractRef: Ref, executionEvidenceRefs: Ref[]}` | From the exact matching `attempt-prepared` only. Resolve every identity and correspondence unchanged. Evidence references must be returned by the admitted authority/precondition/adapter mechanisms and show the current decision or applicable standing grant, validity, revocation/withdrawal checks, dependencies and adapter readiness for this exact command. Validate those contracts at permission time; refs alone are not proof. An unavailable authority source refuses permission. Only the invocation that durably receives `created` may dispatch this bound command once. |
| `pre-send-refused` | `{attemptRef: Ref|null, reason: "cancelled"|"superseded"|"decision-denied"|"decision-withdrawn"|"authority-unavailable"|"authority-invalid"|"proposal-expired"|"precondition-failed"|"adapter-unavailable"|"recovery-blocked", evidenceRefs: Ref[]}` | From `effect-open`, `proposal-revised`, `attempt-prepared`, or `retry-eligible`. `attemptRef` identifies the current prepared-but-not-permitted attempt, or is null when refusal occurs before preparing a new attempt. Older attempts and their permissions remain in the fold and are not erased by this null value. Evidence supports the refusal reason. Refusal is not success or uncertainty about sending: this transition is permitted only when no send permission exists for that attempt. Further work requires newly validated evidence and, if semantics changed, a new proposal revision. Refusal never reactivates an intent cancelled or superseded in its governing intent journal; a cancelled intent cannot resume this effect via the pre-send-refused branch. |
| `cancelled` | `{intentRef: Ref, cancelCommandRef: Ref, reasonRef: Ref}` | From any noncancelled chain head, including after a send permission. Resolve an admitted L-I06 cancel command for this exact intent and authenticate its actor/owner scope. If this cancellation is already resolved in the current journal view before permission admission, it prevents that permission. If its source is concurrent or not yet visible, this design does not claim atomic order across the interaction/effect slots. Once the `cancelled` control transition is admitted, no later permission/new attempt is admissible; if it follows a permission, that attempt remains unresolved until evidenced. The chain position determines pre/post-permission semantics; a payload cannot claim the phase. |
| `retry-eligible` | `{priorAttemptRef: Ref, attemptId: BoundedId, proposalRef: Ref, proposalDigest: Digest, recoveryMode: "receiver-idempotency"|"authoritative-reconciliation", observationRefs: Ref[], recoveryEvidenceRefs: Ref[]}` | From a chain head that includes the exact prior attempt's send permission and no cancellation. Resolve all observations and the operator-admitted recovery contract. For idempotency, evidence must establish same stable receiver key, identical bytes, and unexpired receiver key retention. For reconciliation, evidence must identify exact query/result, cover commit and visibility interval, and establish that the old sender and queued transport cannot later commit. The typed evidence and verifier define these claims; no caller-supplied Boolean does. A no-recovery contract, positive match, indeterminate result, contradiction, incomplete interval, live sender/queue, or unavailable evidence cannot produce this event. It only permits preparation after current authority/preconditions are checked again; it never itself dispatches. |

`attempt-observation` here names the existing adapter/provider outcome or reconciliation facts descriptively; it does not introduce a new journal kind or slot. Those ordinary immutable causal journal facts must reference the exact prepared attempt and retain their existing source evidence. Receiving assessment uses the existing L-I06/L-W07 interaction/result-proposal contract and binds an authenticated independent receiver. Neither overwrites prior evidence, changes the effect-chain head, grants permission, or by itself clears uncertainty. They remain independently concurrent. Before a control transition, the regulator resolves and revalidates all applicable observations and assessments it can currently observe. The successor slot serializes control decisions against other control decisions only; it does not promise atomic ordering with a concurrently written/unobserved fact or an external receiving system. A late contradictory outcome is retained and blocks further automatic retry/acceptance, but it does not make a duplicate receiving effect acceptable. Retry is permitted only where receiver idempotency prevents a second effect or the authoritative-reconciliation contract proves no effect occurred and no old sender/queued command can commit later; absent that proof, retain uncertainty and disable automatic recovery.

## Transition graph and invariants

`effect-open → proposal-revised* → attempt-prepared → send-permitted` is the initial path; `proposal-revised` may occur before preparation. A `pre-send-refused` event may be followed by a later proposal revision or a newly prepared attempt only after its cause is resolved and current checks pass. Following a permission, the attempt is never returned to `prepared` and that permission is never reused by a recovered worker. Its observations remain ordinary concurrent causal facts. A valid `retry-eligible` control transition may permit a new physical attempt with the same `effectId`, exact unchanged receiving goal and a fresh `attemptId`; then another preparation and permission. A subsequent proposal revision is allowed only if authoritative reconciliation proves no effect occurred and the old sender/queued transport cannot commit; changing bytes invalidates idempotency-only recovery eligibility and all prior approvals. A material change to bytes, destination, recipient, disclosure, predicate, limits, or receiving goal requires a new proposal revision before any new attempt, invalidates prior decisions, and may require an entirely new effect if the intended receiving effect changed. Only control transitions are admitted against the exact effect-successor predecessor slot. Ordinary observations and assessments remain concurrent journal facts with exact causal references. Before each control admission, resolve the latest control head and all currently observable, applicable facts; if any source is unavailable or contradictory, refuse or hold. This is a read-and-validate step, not an atomic snapshot over concurrent ordinary facts, external authorities, or receiving systems. A later fact is not ordered by the effect slot; the adapter recovery contract must prevent late commits or make duplicate sends receiver-idempotent.

`cancelled` is absorbing for preparation and permission. Ordinary attempt observations and independent receiving assessments can still be appended/resolved after cancellation. Post-permission cancellation does not claim the in-flight effect was prevented: report “may have been sent,” retain the exact attempt, and require recovery/receiving assessment. Compensation is a distinct newly authorized effect. Neither cancellation nor a later worker's read of an existing permission can transfer dispatch capability.

At every control admission the validator folds the entire verified predecessor chain, rejects forks/missing causes/unknown transitions, checks one current head, and verifies that each attempt binds exactly one proposal revision and one effect. Journal uniqueness serializes control transitions only. Concurrent ordinary facts are independently retained and re-resolved before each control decision; an unavailable or incomplete source means stop, never assume no attempt, no cancellation, or no effect.

## Recovery and uncertainty

A durable `send-permitted` with no verified receiving observation is `uncertain`, even if no handoff observation exists. Preserve it through worker death, timeout, cancellation, date boundary and restart. A recovered call may append provider/reconciliation observations under separately admitted read authority but cannot dispatch on the old permission. `retry-eligible` must resolve immutable evidence, not a model-generated summary. For negative reconciliation, the verifier must check exact effect/payload correspondence, receiver query authority, complete visibility/commit interval, sender termination proof, queued-transport disposition, and any contract-specific finality. A missing PID, lease expiry, empty feed, transport exception, or Boolean `safeToRetry` never suffices. If a required proof cannot be resolved, leave the effect uncertain and ask the accountable receiver for assessment; no fresh effect ID or side-channel operation is a recovery shortcut.

A cancellation control transition racing with permission must use the same current predecessor. If the cancellation control transition wins the same effect predecessor slot, no permission is admissible. If permission wins, it is ordered before the later cancellation control transition and its live creator alone retains the one-shot dispatch right; cancellation blocks future attempts but cannot revoke a dispatch that may already be underway. The user cancellation command itself may be concurrently written or not yet visible to the permission check; the design does not claim cross-slot atomicity and must report that evidence boundary accurately. Ordinary attempt observations and receiving assessments do not use this slot and may be concurrent. A control transition re-resolves the known applicable facts immediately before admission but cannot claim an atomic order with facts that arrive concurrently or remain outside the journal. Late outcomes remain attached to their original attempt; they never replace earlier evidence or silently set it accepted. A contradictory late outcome is a serious recovery-contract violation: preserve it, stop automatic retry/acceptance and escalate for accountable resolution; it does not excuse or normalize duplicate effects.

## Unresolved external contracts (blocking implementation, not semantic design)

1. The authority resolver must define evidence types and verification semantics for current personal assignment/provider acceptance/owner grants and actual institutional allocation/delegation, decision validity/withdrawal, and any external revocation freshness. This LLD adds no grant or fallback actor.
2. Each adapter must define admitted contract evidence for exact command correspondence, dispatch/handoff, key scope/retention/payload binding or authoritative reconciliation interval, queued-transport shutdown, response artifacts, and whether delayed outcomes can contradict a final negative query. If that finality cannot be proved, automatic retry is disallowed.
3. The shared journal must define the caller/actor evidence and durable admission result that bind the live `created` result to a non-replayable, call-local, one-shot dispatch capability, and revalidate the currently resolvable observation frontier before control transitions, without claiming atomicity against concurrent/external facts. Restart must never recreate that capability.
4. The receiver-assessment authority and result-proposal contract must define exact receipt/result correspondence and independent receiver evidence. The interaction-level L-I06 payload names only result proposal, disposition and evidence; the trusted boundary must bind receiver identity and assignment/allocation authority without treating those opaque references as sufficient proof.
5. L-J07/L-J08 durability, maintenance exclusion, source discovery, compaction and all direct journal consumers remain prerequisites. This event contract is not accepted storage or operational evidence.

## Acceptance obligations

Derive effectful assays from these variants, not from strings or generated tests alone. Exercise two-process and in-process predecessor races; permission versus cancellation with both winners; concurrent observations/assessments around retry permission, demonstrating source retention and the limits of non-atomic visibility; duplicate/changed proposal correspondence; restart after permission without send-right transfer; cancellation with delayed handoff/outcome; stable receiver idempotency across invocation IDs; and reconciliation with and without sender/queue/visibility evidence. Independently record the receiving effect. Verify delayed observations remain attached to the old attempt and that a receiver—not producer status—accepts/rejects the exact result. Local process termination does not prove power-loss durability or external receiver finality.
