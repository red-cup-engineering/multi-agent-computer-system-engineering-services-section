## Effect and source evidence

L-O03/L-O04/L-O06 and L-M07 require consumers to distinguish retained input from admitted evidence and to preserve failures through the work-selection path. A recorded request must not become execution authority merely because a receipt has an event identifier. Preserve original event identities, row occurrences, causal state, actual admission transitions and membership observations. Remove fictitious per-event physical locations and the conversion of consumer exceptions into malformed-data counts. These are refinements for the connected journal replacement, not permission to patch the old writer as an independent endpoint.

The source-bound evidence alongside this document identifies the current writer, segment admission, receipt schema, facade, RPC witness and actual receipt-consuming entrances. Current writeIndexRows synthesizes eventPath even when physical custody is a segment, then omits the segment result's admission state. Current scanCausalEvents catches both row conversion and the consumer fold and labels either failure malformed. Existing receipts are migration evidence for the useful event correspondence, not authority to preserve either loss.

## L-R01 — One protected ordinary-admission operation

Ordinary appendRows/appendEvents run entirely in one L-O01 owner scope. Derive their feed using the existing pure address laws, verify it belongs to that owner, snapshot and validate all inputs before source mutation, and construct witnesses/packets with the existing accepted Code transformations. Retain source entries through publishRetained; do not call the segment writer, create a dated source projection, or reacquire a public journal operation from within the scope. Packet handling remains L-O19 and must retain its complete source correspondence.

Capture the requested feed's admitted event-reference set before publication. After refresh, inspect each input's exact witness state and the same feed's admitted set. Do not substitute root-wide admitted deltas for feed membership. A source that cannot be verified fails the complete operation; not-witness after supposedly retaining a valid input is a source-corrupt refusal, not a successful receipt.

Before returning, requireDurable for the ordinal distinct set of input events that are now admitted, using uniqueSlot null and the exact required artifact set. Its expansion supplies the full causal/artifact closure. Pending or blocked sources can have durable source custody but cannot receive an admitted-closure acknowledgment. The receipt below makes that distinction explicit. A failure after possible publication retains the owner's publication-uncertain precedence and leaves visible sources for later recovery.

An empty rows/events input still enters and validates the owning journal before returning an empty receipt. It creates no empty batch and does not provision missing storage. Invalid inputs, source failures, and callback failures retain their distinct error semantics.

## L-R02 — Truthful row-write receipts

Keep the existing observation base fields, operation write-statement-rows, feed artifact handle, rows and appended, with the existing boundary schema identity. Make statements required, including the empty array. Replace each old {id,path,written} entry with the closed immutable {id,written,admission,membershipAdmittedNow}. No per-event filesystem path survives. The feed artifact remains a logical address; its presence does not assert that a dated file exists.

id is the exact normalized input witness identity. admission is admitted, quarantined or blocked, taken from the final protected owner view. written is true exactly when that input event is in the operation's root-wide newly admitted event set; it is false for newly retained pending/blocked input and for an already admitted event receiving another feed membership. This preserves the old segment admission transition meaning without pretending that it counts every storage effect. membershipAdmittedNow is true exactly when the event is admitted in the selected feed after the operation and was absent from that feed's admitted set before it. It describes an admitted-membership transition, not whether pending custody previously existed.

Keep one entry for each input row occurrence in input order, including repeated identical rows. Equal identities receive equal transition/state values. rows is the input occurrence count; appended is the number of entries whose written is true. Consequently appended is an input-occurrence measurement, not a distinct-event, physical-write, retained-source or new-membership count. Consumers needing distinct events explicitly deduplicate identities; consumers needing feed custody use L-M01. Do not silently reinterpret this existing field as physical throughput.

The exact public return value of FilesystemJournal.appendEvents(log, events, artifacts = []) is a deeply immutable array, in original input order, with one closed {statement,written,admission,membershipAdmittedNow} entry per input event occurrence. There is no outer receipt object and no logical-address metadata in this return value. Empty event input returns the frozen empty array after the operation completes, including artifact-only retention when artifacts were supplied. statement is the verified normalized immutable witness, not an alias to caller-owned mutable input. Both operations obtain before/after facts inside the same scope and let final owner binding/cleanup complete before the result escapes.

## L-R03 — Execution consumers require actual admission

Migrate the receipt schema, producers and consumers in one connected generated source group. RPC journal witnessing, CLI/HTTP/web arrival-to-invocation adaptation, monitoring and hook linkage must not extract every id and treat it as a ready causal predecessor. Before producing a durable admission acknowledgment, admitting a follow-on invocation, updating a causal head or executing work, require every relevant entry to have admission admitted and the publication/closure operation to have succeeded. A pending or blocked entry yields the existing explicit obstruction/incomplete surface; it never becomes an empty cause list, a successful no-op, automatic retry dispatch or an invented initial interaction.

An already admitted duplicate has written false and remains usable as a verified causal predecessor. Repeated receipt occurrences do not duplicate the causal-reference set. membershipAdmittedNow does not grant execution authority, and written true does not establish a personal assignment, current grant or independent receiving. The unique interaction/effect domains still use L-J06/L-O05 and their original occupied-command closure, rather than interpreting ordinary append as request-key uniqueness.

Retained pending work can later become admitted when evidence arrives. Queries then resolve that original event; they do not rewrite its observation time or create a substitute request. Historical receipts remain historical observations and are not reinterpreted as current authorization.

## L-R04 — Consumer fold failures are not malformed source

All scans validate the complete selected source and causal ordering before invoking a consumer fold, within the owning protected operation. Reuse the existing EAVT conversion and causal ordering laws. When the scan's documented contract permits ignoring a non-row observation, increment malformed only for a payload that is not an EAVT row or fails the explicit row conversion. Limit any catch to that conversion. Corrupt source custody, causal-order failures, resource limits and storage diagnostics fail the operation.

Call the consumer fold outside the row-conversion catch. Any value it throws, including undefined, must escape unchanged subject only to the already specified publication-uncertain precedence; owner cleanup still occurs. Do not increment malformed, continue later rows, return a partial accumulator, or replace the thrown value with cleanup errors. A fold returning a normal value retains its existing accumulator/count semantics. This rule applies to feed, date, territory, subject and as-of forms that expose a caller fold, not merely the helper currently named scanCausalEvents.
