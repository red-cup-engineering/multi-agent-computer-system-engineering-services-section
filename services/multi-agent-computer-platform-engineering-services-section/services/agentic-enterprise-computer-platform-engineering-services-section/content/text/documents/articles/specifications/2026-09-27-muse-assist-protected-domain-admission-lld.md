## Derivation and effect

This closes the concrete adapter interface required by L-O05, preserving L-J01–L-J07 and L-C02/L-C03. A current authorized caller can create one durable semantic command or resolve the original command at its occupied retry key. Retain the source owner, unique wire construction, immutable references and existing durability barrier. Remove any need for a caller to pair an unchecked journal string with an owner, supply a Boolean authority verdict, append duplicate ordinary rows as retry handling, or treat source custody as execution permission. The new adapter is trusted Systems composition over those existing capabilities, not a scheduler, public generic append endpoint or proof that personal domain authority exists.

## L-D01 — Construction and bound registration

The internal Systems factory is createUniqueAdmission(storeDirectory, registration). Its only returned operation is admit(command). The registration is privately copied and frozen; the caller need not freeze its input. It has exactly journal, domain, principal, validate, authorizeNew, authorizeOccupied and now. journal is the exact nonempty at-most-512-scalar host identity; domain is interaction or effect-successor. The remaining fields are trusted synchronous functions. Validate construction without invoking them; reject inherited, accessor, missing, extra or malformed registration properties. Copy the primitive values and function identities into private state so caller mutation cannot change registration. This is a process capability supplied by trusted host composition, never JSON request material or inference output. No runtime register/unregister API is added.

Construct the owner using openSourceOwner(storeDirectory, registration.journal). This uses the accepted expected-identity check; do not separately parse host.json or expose the root/owner to handlers. A constructor storage failure propagates its existing branded diagnostic; construction does not provision storage. Returning a factory object establishes storage binding, not a domain grant. Each admit call obtains fresh principal and authority decisions; no positive permission is cached.

## L-D02 — Snapshot and principal association

Before entering the source owner's operation, derive the canonical immutable command through addressUniqueJournalCommand(command, journal), retaining its commandRef and slotDigest. Reject a mismatched registered domain as invalid. Invoke principal() once per call to obtain the authenticated principal as an exact scalar string. This source belongs to the host's authenticated call capability; a request field cannot substitute for it. For interaction, additionally require command.key.principal to equal this principal. The domain's validate(canonicalCommand, principal) is a pure function returning exactly true or false; false means invalid. It verifies the concrete domain body and context/principal association. It performs no IO or authority evaluation. Neither principal nor validate may return a Promise/thenable or another unsupported type.

Wire construction failure carrying the existing unique-journal-invalid diagnostic and validate false produce the domain refusal below before owner entry or mutation. A malformed principal or interaction principal mismatch is forbidden. An invalid trusted registration, unsupported callback result or thrown callback failure remains a host implementation failure and propagates to the host's sanitized failure boundary; do not relabel arbitrary exceptions as missing evidence or allow them. In particular preserve a callback throwing undefined. No logging of request, principal, paths or exception details is introduced.

## L-D03 — Protected read view and authority results

After snapshot validation enter exactly one owner.withOperation call. Create an immutable read view exposing only witness, artifact, feeds, events and sourceStatus, forwarding to that live scope. It cannot publish, initialize, read arbitrary files, reacquire the journal, retain the gate or supply serialized durability evidence. Forwarded methods retain the original owner's lifetime and errors, so a retained view refuses after completion. Registered authority callbacks are trusted domain code, not request-provided functions; restricting the view prevents accidental storage mutation through this interface but does not sandbox arbitrary trusted JavaScript.

Read scope.uniqueRecord(slotDigest). For verified vacancy call authorizeNew(view, canonicalCommand, principal). For occupancy call authorizeOccupied(view, canonicalCommand, principal, originalEntry). originalEntry is the exact parsed immutable owner result; reverify through parseUniqueJournalRecord(originalEntry.record, journal, slotDigest) before using its reference. A stored record is not permission to reveal it. Neither path may call the other authority function as a permissive fallback.

Both authority callbacks return exactly false for denial, or the immutable-by-snapshot closed object {events, artifacts, retainedArtifacts}. events and artifacts are ordinal-distinct verified reference arrays identifying current authority/dependency evidence that this decision requires durably retained. retainedArtifacts is the ordinal-distinct exact {ref,canonicalText} array for the new record's direct external artifact sources under the existing uniqueJournalRecord contract. Occupied authorization must return an empty retainedArtifacts array; it cannot replace or supplement the occupied command. Snapshot and bound the full result using the existing JSON_RESOURCE_ENVELOPE and validate reference/entry shape. A Promise, missing field, duplicate reference, invented body, unsupported result or callback exception is a host failure, never authorization. false produces forbidden without returning occupancy, timing metadata, source counts, original command or reference.

The concrete domain interpreter must establish current grants, proposal/assignment/predecessor correspondence and applicable restrictions from the admitted view. It must not accept a schema-valid issuer assertion as provenance. This adapter verifies result shape and custody, not the truth of arbitrary callback code. Fixture callbacks prove orchestration only. Production registration requires separate accepted implementations of both domain checks.

## L-D04 — Vacant transition and durable source correspondence

For allowed creation, current authority evidence returned in events must be included directly in command.causes; authority artifacts returned in artifacts must be included directly in command.artifactRefs. This makes the decision's declared evidence part of the persisted command and prevents an unrecorded grant from being described as retained provenance. Domain validation may include other causes/artifacts as required; array order remains the existing ordinal wire law. Missing correspondence is a host-contract failure before publication.

Invoke now() only for a permitted vacant creation, obtaining the exact existing UTC timestamp format accepted by uniqueJournalRecord. Build the record with {journal, seat: principal, admittedAt, artifacts: retainedArtifacts}. The pure builder verifies the exact external artifact set, bodies, reference correspondence and aggregate envelope before source mutation. Do not fetch caller URLs, use paths as artifact references, manufacture artifacts for missing witnesses, add retry observation time to semantic identity or rewrite the canonical command to fit an authority result.

Before publication, requireDurable for the ordinal distinct union of command.causes and authority events, plus authority artifacts, with uniqueSlot null. This verifies existing predecessor/authority custody. Direct external artifact bodies included in the new envelope are verified by the pure constructor and obtain their source custody through publication and the final closure barrier; they need not be copied into a second prior source. Domain proof artifacts identified in the authority result do require existing custody. Their declared authority cannot first be invented by the command whose admission they authorize.

Call publishUnique(record) once. If it returns created, verify its authoritative entry corresponds to the exact canonical command and slot, then requireDurable with uniqueSlot {journal,slotDigest}, events and artifacts from the allowed authority result. The owner expands the new original command's entire retained closure. Return created only after owner final binding/cleanup succeeds. If publication unexpectedly returns existing, run the occupied path against its authoritative entry, including authorizeOccupied and its original closure, and never return created. This branch is defensive under the gate; its existence does not license concurrent unprotected writers.

## L-D05 — Occupied resolution and original acknowledgment

Authorize the proposed retry's principal/context association before returning any occupied reference, and independently authorize occupied resolution as L-D03 requires. A changed proposal does not gain access merely by guessing the key. Do not invoke now, construct a replacement record, require the conflicting proposal's causes/artifacts to exist, or invoke authorizeNew on the normal occupied path. Complete requireDurable using the original uniqueSlot plus the current occupied-authorization events/artifacts. This includes the original command's full predecessor/artifact closure even when the proposed command differs. Current resolver authority evidence can differ from historical creation authority; it need not be written into or change the original immutable command. No occupied result transfers dispatch rights, refreshes original observation time or creates another intent/attempt. ## L-D06 — Result and failure ownership

The trusted adapter returns one of two closed envelopes: {kind:"refused",code:"invalid"|"forbidden"}, or {kind:"admission",result}. result is exactly an existing L-J06 storage result: {disposition:"created",reference}, {disposition:"existing",reference}, {disposition:"conflict",reference}, or {disposition:"unavailable",reason}. The tag is disposition, never kind inside result. An outer kind:"admission" does not replace that nested discriminant. reason is one of the existing seven reasons. This wrapper distinguishes domain refusal without adding storage reasons or reinterpreting unavailable as absence. Deeply immutable outputs contain no roots, callbacks, scope handles, source bytes or internal diagnostics.

Catch only the owner's genuine branded journal-unavailable values and convert their reason into the storage unavailable result. A forged code/reason object is not that brand. Arbitrary host/callback failures propagate unchanged for the prepared host to sanitize; they cannot become an invalid user request or a successful empty result. The adapter does not define HTTP status, disclose context existence or produce an RPC witness on its own. L-C09's prepared boundary maps these internal outcomes under the authorized context. Public production routes remain unmounted until that connected boundary is accepted.
