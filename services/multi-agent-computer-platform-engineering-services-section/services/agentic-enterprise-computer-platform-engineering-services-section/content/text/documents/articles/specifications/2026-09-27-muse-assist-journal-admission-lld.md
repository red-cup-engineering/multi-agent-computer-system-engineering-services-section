## Receiving effect and dependency order

This refines L-E01–L-E04 and L-E08, including L-I02's request replay and L-W02's stable references. A caller can retry an admitted command and recover its original reference; competing workers cannot each acquire the right associated with the same effect successor; ordinary journal queries retain these facts across dates and restart. The carrier is the owning causal journal. Retain existing witness identities, causal/source validation, and useful feed/subject projections. Do not introduce a Muse-owned record authority or treat an invocation receipt as effect reservation.

The command/envelope laws belong to the Code layer and use Data's canonical JSON/content identity. Physical source retention, durable publication, recovery, discovery and compaction belong to Systems. The current location of a filesystem implementation inside the Code package is migration evidence, not a license for a new upward dependency from Code to Systems. Fabrication must place new physical persistence in the shared journal's System implementation and account for existing direct readers/writers of the same carrier.

## Closed command and identity contract

**L-J01 — Semantic command.** The canonical command is a closed JSON object with exactly `kind`, `version`, `domain`, `key`, `subject`, `value`, `causes`, and `artifactRefs`. `kind` is `metroplat.journal.unique-command`; `version` is integer 1. `domain` is `interaction` or `effect-successor`. `subject` is the exact journal subject, a nonempty string of at most 512 Unicode scalar values. `value` is a JSON value validated by the domain contract before admission. JSON values must satisfy the repository's existing JSON admission/canonicalization contract; nonfinite numbers, undefined values and non-JSON values refuse. Admission uses the existing `JSON_RESOURCE_ENVELOPE` for the whole command and, separately, the whole retained envelope: 1,048,576 source/canonical UTF-8 bytes, depth 64, 100,000 nodes, 4,096 members per object, 65,536 elements per array, 262,144 UTF-8 bytes per string, and 1,024 bytes per key. The 512-scalar identifier bound additionally applies. Reject unpaired surrogates rather than replacing them or normalizing identifiers. No Unicode normalization, trimming or case folding changes identity. Boundary transport size limits precede parsing; bounded JSON admission precedes canonicalization/hashing. A valid command whose complete retained envelope exceeds the bound is refused before publication; it is not silently truncated. A changed resource envelope requires a versioned contract revision, not an environment-dependent interpretation of version 1.

For `interaction`, `key` is a closed object containing exactly nonempty bounded strings `context`, `principal`, and `requestId`. For `effect-successor`, `key` contains exactly `journal`, `effectId`, and `predecessor`; journal/effectId are nonempty bounded strings and predecessor is null or an exact existing witness content reference. Each bounded key string has the same 512-scalar maximum. `journal` must equal the deployment-bound owning journal identity. Context/principal bindings come from authenticated interaction admission; a generic command parser does not establish them.

`causes` and `artifactRefs` are arrays of unique valid artifact references, sorted by ordinal code-point order for canonical representation. Reject duplicates and noncanonical order rather than silently changing a signed or compared command. An effect command with nonnull predecessor must include that exact reference in causes. The explicit null predecessor denotes initial admission, never a recovery shortcut. The effect-transition validator independently determines whether this predecessor and command are lawful; generic journal admission is not that validator.

**L-J02 — Stable bytes.** Encode the closed command with the existing `canonicalJson` implementation, UTF-8, without a trailing newline. Its content identity is the existing `addressArtifact(command).ref`, verified using the matching existing artifact verifier. Do not introduce a second JSON serializer or ad hoc digest format. Observation time, worker invocation/attempt identity outside the domain value, boundary caller metadata, local root path and retry arrival time are not automatically added to these semantic bytes.

The unique slot digest is lower-case SHA-256 hex of canonical UTF-8 JSON for `["metroplat.journal.unique-slot",1,journalIdentity,command.domain,command.key]`. `journalIdentity` is operator-bound service identity, never a filesystem path or a caller-selected substitution. Hashing this typed tuple avoids delimiter/path ambiguity. Neither command content nor observation time is in the slot key: changed content must conflict at the same occupied key. These digests are internal storage identifiers, not grants or unguessable access tokens.

**L-J03 — Same command versus new observation.** Canonically identical commands at one slot return the first admitted witness and original observation time. A subsequent boundary time cannot create another record or change the returned identity. Any canonical command change at that slot is a conflict, even if the new command appears preferable or the old grant has expired. Authorization to resolve an existing record is rechecked; knowing a retry identifier cannot reveal another context's input. A conflict in effect succession causes the regulator to read and validate the occupied successor; it does not license overwriting it or selecting an unrelated predecessor.

## One retained journal fact

**L-J04 — Witness correspondence.** The existing journal witness representation is retained. The admission observation's payload is the ordinary EAVT row `[command.subject,"metroplat.journal.unique-admission",command,admittedAt]`. Its claim is the existing typed mark `metroplat.journal.unique-admission`; its address is `tm.mark(eavtKey(row))`, using the existing typed-term constructor rather than passing the key string as a term. Its causes equal command.causes; its referencedArtifacts equal command.artifactRefs; its observation seat is the admitted caller. `causes` and `referencedArtifacts` here describe the observation: the witness constructor additionally includes its own boundary artifact in the witness core, which must not be stripped to force core-level equality. Construct and verify the witness with the existing journal-witness/artifact laws; do not accept a caller's alleged witness ID without that verification.

`admittedAt` is a boundary-generated UTC timestamp in exact `YYYY-MM-DDTHH:mm:ss.sssZ` form representing a real instant. It is retained with the first admission and excluded from the semantic command comparison. The caller is a nonempty authenticated principal identifier bounded to 512 Unicode scalar values and supplied by the trusted boundary. For an interaction witness, the admitted caller equals command.key.principal; a worker service cannot replace that authenticated origin with its own identifier. Neither caller nor time is inferred from model text. Newly constructed witness source arrays use ordinal reference order, independent of the process locale. Verification of an older ordinary witness may accept a permutation of the same exact verified source set without changing its witness ID, core, observation or source bodies. Missing, duplicate, surplus or changed sources still refuse. A new version-1 unique record uses the canonical order; historical ordinary source bytes do not need rewriting to recover their capability.

**L-J05 — Retained record.** The immutable source envelope is a closed object with exactly `kind`, `version`, `journal`, `commandRef`, `witness`, and `artifacts`. `kind` is `metroplat.journal.unique-record`; version is 1; journal is the configured identity; commandRef is L-J02's content reference; witness is L-J04's verified witness. Artifacts is a reference-sorted array of closed `{ref,canonicalText}` objects. Its reference set is exactly `command.artifactRefs` minus the reference set in the verified witness's own sources. Each remaining reference occurs once, with independently verified canonical JSON text, byte-equal to `verifyArtifact(ref, canonicalText).canonical.text`; alternate whitespace/encodings refuse. Each subtracted reference must resolve to its verified witness source body. References already present in those sources must not be repeated in artifacts. Missing, surplus, wrong-address or contradictory content refuses publication.

Recover the command, slot digest, subject, caller and time from the verified witness and configured identity. Do not maintain independently editable copies of those values in the envelope. Store canonical envelope JSON plus one final newline. The root-relative source path is `unique-admissions/v1/<slotDigest>.json` beneath the existing owning journal directory. Neither subject, principal, request text nor effect ID appears directly in that pathname. Staging files are never admitted sources. Use L-E03's durable create-only publication; verify envelope canonical bytes and filename correspondence on resolution.

**L-J06 — References and results.** A successful receipt returns the immutable reference `{journal,subject,event,payload}`: journal is the configured service identity, subject the exact command subject, event the existing witness ID, and payload the canonical command's content reference. No local file path is a public locator. This is a concrete L-W02 reference; resolution verifies all four fields and the expected unique-admission kind.

Admission returns a closed tagged result: `{disposition:"created",reference}`, `{disposition:"existing",reference}`, `{disposition:"conflict",reference}`, or `{disposition:"unavailable",reason}`. Reason is exactly one of `storage-unavailable`, `storage-unsupported`, `source-corrupt`, `evidence-unavailable`, `resource-limit`, `maintenance-busy`, or `publication-uncertain`. Unsupported storage semantics use storage-unsupported; malformed or wrong-address retained bytes use source-corrupt; an unresolved required reference uses evidence-unavailable; exhausted bounded traversal uses resource-limit; failure to acquire required maintenance protection uses maintenance-busy; a failure after publication may have become visible uses publication-uncertain; other host I/O failure uses storage-unavailable. Classification must never assert that a failed publication did not occur. Private diagnostic evidence is retained by the boundary; raw paths, credentials and exception strings are not public reasons. Invalid command/identity/authority is refused before storage; it must not be mislabeled unavailable. A denied caller receives no occupied reference. Only a verified successful publisher can receive created. Existing/conflict are returned only after verifying and completing both the occupied source's and its required closure's durability boundaries under L-J07; they never transfer dispatch rights. Any uncertain publication, corrupt source or unresolvable required evidence yields unavailable and cannot be translated to absence.

The public resolution outcomes remain L-W02's resolved/unavailable/forbidden/invalid distinctions. Absence of a slot can be used only by the local create-only admission operation after authenticating the context; a remote query cannot turn an unavailable record into a new initial effect.

## Causal retention and recovery

**L-J07 — Required closure before acknowledgment.** Before acknowledging created, existing or conflict, establish durable retention of the witness's complete required causal/artifact closure, including earlier request, assignment, proposal and authority evidence used by its domain contract. Verifying that bytes can currently be read is insufficient: their source files may not yet be synchronized. The retained record carries its direct external artifact bodies; predecessor witnesses and their source bodies must remain durably resolvable in the same owning journal or an explicitly admitted durable external custody service. Resolve cycles, missing causes, incorrect digests and resource-limit overflow as refusal/unavailable; never truncate the required closure or call a Boolean supplied by inference proof of persistence.

The System persistence implementation must expose a real durability barrier over the required retained source set and its directory entries, and return evidence identifying the content protected by that barrier. For an occupied slot, resolve the stored command's closure, not the rejected caller's alternative command. An existing reader must synchronize the source file and every ancestor directory through the filesystem root, because it cannot infer which ancestor creations an interrupted publisher synchronized. A verified deployment initialization barrier may discharge ancestors above the journal only if that exact root binding remains valid; merely observing that a directory exists cannot. The barrier protects the exact content references verified during this call; a generic success flag or a receipt for another closure cannot discharge it. Deduplicate shared source files within one barrier. Ordinary segment files can contain more evidence than the selected closure; synchronizing a containing file is acceptable, but does not expand the caller's authority to read or disclose its other content. Existing already-durable unique records can satisfy predecessor custody without copying the whole ancestral chain into every child record. Do not create quadratic copies of causal history.

Destructive compaction/retention must preserve these identities and source availability: verify and durably publish replacement source content before removing the old representation, and protect unresolved work's required evidence from retention deletion. Admission and destructive maintenance must have an enforced ordering covering closure discovery, byte verification, source-file and directory synchronization, slot publication, and acknowledgment. Maintenance cannot delete or replace a source between discovery and acknowledgment. If another caller completes an interrupted slot, it acquires the same protection and repeats the unresolved closure barrier before acknowledging it. An immutable slot's existence alone is therefore insufficient to skip source retention. A comment, stale PID or caller assurance is insufficient. The exact host maintenance/barrier interface and its consumers must be closed in the storage fabrication order before this admission API is enabled. The accepted durable create-only helper supplies publication, not this whole-source barrier or maintenance exclusion.

**L-J08 — Source precedes index.** Reconstruct admission state from retained verified witness sources whenever a derived index is absent or incomplete. A present index file is not proof that it contains every published witness. Specifically, interruption after segment publication and before its admitted-index append must not make a retained predecessor appear unknown or leave its dependent permanently quarantined. Repair may append derived entries, but cannot invent source witnesses or accept an invalid causal closure. Reads of source and derived state must converge without manual deletion of indexes or restarting the entire service.

Distinguish the actual roles of the current `index/causal-admission/v2` files: the admitted lookup is derived from retained source segments; externally referenced artifact bodies and pending witness bodies may have no other current copy. Do not erase an entire directory merely because it is named index. Migration must retain those actual source bodies and their identity/causal properties before retiring the old representation.

**L-J09 — All relevant reads.** Extend exact artifact resolution, per-feed reads, row folds, as-of causal reads, subject/date/territory discovery, source-status queries and compaction to include unique admissions. Readers must deduplicate by verified witness ID when a source also has a normal segment projection. A normal segment copy cannot prove that the unique slot still exists; effect ownership and command replay resolve the authoritative slot directly.

A source-only admission must remain discoverable even if interruption prevented every optional projection/index write. Slot creation under an existing directory must invalidate any discovery cache that would hide it. Do not rely only on dated-directory timestamps, because the selected source namespace is date-independent. Date and subject filters use the verified first witness's time and exact subject, not pathname guesses. A request retried tomorrow resolves its original slot and reference. Unreadable/corrupt source or a resource limit must not be caught and returned as an empty feed, absent command, or permission to repeat work.

Derived lookup caches are permitted, but their invalidation and rebuild behavior must be demonstrated. The physical source-discovery strategy must bound reads and avoid re-verifying unrelated historical artifacts on every admission. This is an implementation obligation, not permission to hide undiscovered facts behind a resource limit. A limit produces an explicit unavailable result.

## Migration observations and required acceptance

A controlled [recovery observation](evidence/2026-09-27-journal-admission-recovery/observation.json) retained an admitted witness in its segment, removed only its derived admitted-index entry, cleared process caches, and submitted a dependent. The source witness remained readable, while its recovered admission state was absent and the dependent stayed quarantined. This is a constructed partial-index image corresponding to the source/index publication gap, not a simulated power outage. It establishes a missing recovery behavior that must be corrected before unique admission is treated as complete.

The affected current System consumers include `readEvents`, `eventFiles`, `scanSourceFilesInternal`, `listDailyFeedsAtDirectory`, `subjectLogPathsInternal`, `territoryLogPathsInternal`, `territoryStructuralSignature`, `readArtifactSource` and `compactJournalStore`, plus the public journal API. The current compact store supplies segment admission, causal state/artifact lookup and legacy compaction. Its direct semantic-record readers/writers are additional consumers of the same evidence family; they must not become an unverified bypass or force a new System dependency into Code.

Independent acceptance must demonstrate: same command/time-varied retries returning one original reference; changed-command conflict; two processes and two in-process workers with one created result; exact source/reference verification; cross-date/subject reads; restart with source publication but no projection; a partial existing admitted index; missing/corrupt cause retention; failed durability barrier; compaction while work remains unresolved; and explicit unavailable rather than empty reads. Exercise actual storage effects, not only the typed parser. Application acceptance additionally requires authenticated intake and effect dispatch through these contracts; this document and the lower publication primitive do not supply that complete workflow.

## Closed wire law and remaining fabrication boundary

The command, content identity, witness correspondence, immutable envelope and receipt shapes above are Code/Data laws. Their independent acceptance must include unchanged command identity across admission times, changed-content conflict, exact tuple domain separation, Unicode identifier distinctions, unknown-key refusal, malformed/noncanonical references, aggregate envelope overflow, and observation/core boundary-artifact correspondence. Those pure laws can be fabricated separately once their source placement and exact exported interfaces are specified. Passing those checks does not authorize storage admission or sending.

Physical integration remains a single dependent work family: source discovery and partial-index recovery, a real closure durability barrier ordered against destructive maintenance, ordinary and unique source readers, and authenticated domain admission. L-J07 does not select a host locking implementation by implication. The storage order must specify its mechanism and all destructive consumers before enabling this API. Domain-specific interaction payloads and effect-transition validation also remain required; a command with a syntactically valid `value` has no authority solely because the generic codec accepts it.
