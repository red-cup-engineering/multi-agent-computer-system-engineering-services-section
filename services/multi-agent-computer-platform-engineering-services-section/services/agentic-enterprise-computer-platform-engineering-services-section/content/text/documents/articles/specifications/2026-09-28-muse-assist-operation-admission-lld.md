## Useful effect and derivation

L-C03/L-C08 require the operation a participant is permitted to use to be the operation actually invoked, with the same personal context and input contract. This refines F-C01. Preserve typed operations, explicit catalogs, portable pure composition and lazy discovery. Remove silent admission-field loss, same-name executable substitution, first-schema-wins caching, and ambient schema completion from descriptor rehydration. The declaration boundary supplies no personal grant, work assignment or execution authority by itself.

The receiving carrier is an installed operation declaration and its exact executable resolution. The source observations in evidence/2026-09-27-operation-admission-design demonstrate that the current constructor discards admission, an alias loses read declarations, the lazy loader executes a different-reference same-name operation, and conflicting same-ID schema descriptors reuse the first schema. Source identity and test totals do not replace observation of the corrected route.

## L-OA01 — Installed admission and bounded snapshots

The admission representation remains exactly the L-C08 schema (2026-09-27-muse-assist-operation-admission.schema.json, SHA-256 fa8aed96f6142e4dedd7dcdd1e24fbbd5acd1318d31de3025995e91253dd7974). Absence preserves an unmarked operation's existing authority contract. An own admission property with undefined, null, extra keys, unsupported version or unknown action is invalid; it is not absence. Personal admission is trusted installed metadata, never selected from invocation arguments. Snapshot that metadata through canonicalizeJson(value, JSON_RESOURCE_ENVELOPE) before property-based validation; rejected accessors/prototypes must not execute. Keep the snapshot deeply immutable on the operation, operation descriptor and program object. Extend ProgramSchema to describe this optional exact property and L-OA03's personal schemaBindings. The two properties occur together; neither is independently accepted from a caller as a permission verdict.

Personal operation construction requires an explicit domain. For command-kind, its complete canonical schema must equal the normative 2026-09-27-muse-assist-interaction-body.schema.json (SHA-256 7c2ba3acd59a1a559aaad70f68359f20042d92e5549fe0c841c9303321b7b22e), with no external reference definitions. The fixed shared artifact identity of that schema value is `ni:///sha-256;o1aiJfFCHVknAEvfyvPZD5gvAsZC2y3N29OVLkhc_dk`, computed with the actual shared artifactId implementation and recorded in normative-identity.json. Use this admitted expected identity, never an expectation derived from the proposed domain itself. This accepts the actual five-branch root oneOf representation; do not require nonexistent root properties.context or infer validity from a matching $id. Annotations are included in canonical equality: changing this exact installed contract requires a new admitted schema version/specification, not a hidden semantic-equivalence heuristic.

For read and artifact, the recognized domain form has a direct object root, additionalProperties:false, a properties record containing context with literal type:string, and a required array containing context. ## L-OA02 — Exact finite schema universe

SchemaContract.id is the schema's declared $id; it is not necessarily a content address. Compare bodies and reference environments, not just these IDs. Normalize a domain or codomain to the closed canonical data value `{kind:"metroplat.rpc.schema-closure",version:1,root,schemas}`. root is its exact nonempty string ID. schemas is the array of `{id,schema}` entries for the root and the entire explicitly supplied transitive reference universe, sorted by UTF-8 bytes of id. IDs are exact Unicode scalar strings with no normalization. Each schema is an object whose $id equals its entry id. The root appears exactly once. Distinct IDs may have identical bodies only insofar as their distinct $id values permit. Repeated occurrences of an ID must have canonically equal complete bodies; disagreement refuses the whole graph before cache reuse or validation.

This value is a temporary content projection of the installed contract, not another registry or maintained manifest. Every traversal is bounded by the shared JSON resource envelope and terminates by object/ID tracking. Reject accessor/prototype/non-JSON material in schema data before inspecting it. Runtime reference cycles are allowed when they describe a finite consistent graph; cyclic JavaScript schema values are not JSON. Repeated-ID descriptor stubs with empty references are valid only as repeated descriptions of a graph member with the same body. Every occurrence's supplied references participates in the universe; do not stop at a cached ID and skip a conflicting descendant. The union is the explicit available reference environment, not a claim about reachability or a license to consult ambient schemas.

The existing descriptor wire shape remains `{id,schema,references}`. Emit it deterministically as the root and a sorted flat references array of every other universe member, each `{id,schema,references:[]}`. A root self-reference is supplied by the root itself. Accept old finite nested descriptor representations only when normalizing every occurrence yields the same closed universe. Property insertion order and reference-array order do not change the normalized identity; extra unused referenced definitions do, because they change the available environment. Do not use JSON.stringify insertion order or localeCompare as canonical equivalence.

## L-OA03 — Personal contract identity and projections

For a personal operation, compute schemaBindings exactly as `{domain:artifactId(domainClosure),codomain:codomainAbsent ? null : artifactId(codomainClosure)}` using the existing shared artifact identity function. Include both admission and schemaBindings in the existing content-addressed operation declaration. Include them on the runtime operation, operationDescriptor and programObject. A change in action, metadata, root schema body, any referenced schema body, or the explicit reference universe changes a personal operation reference. A same-$id body substitution cannot keep the old permission-target identity. No new digest algorithm or separately maintained binding table is introduced.

Preserve all existing declaration fields, including reads, writes, options, formats, effects, relation and host/SEN body identity. For an operation with neither personal field, the declaration bytes and reference remain unchanged by this addition. Correcting an alias which previously discarded nonempty reads/writes is an intentional declaration change: downstream grants/descriptors must use the corrected identity, never an old-ref compatibility override. A correctly declared unchanged unmarked operation must not be renamed or readdressed merely because the schema loader becomes explicit.

operationDescriptor carries the full canonical schema universe in the existing wire form as well as the personal bindings. Verify supplied bindings against that universe. programObject is a descriptive projection carrying the bindings and existing schema IDs; it is not sufficient to reconstitute an executable or grant authority. operationUtterances also carries a fact with predicate metroplat.action.admission and the exact admission value, and a fact with predicate metroplat.action.schema-bindings and the exact bindings. These are descriptive facts, not authorization witnesses. Unmarked utterances stay unchanged.

## L-OA04 — Data-owned closed schema construction

Use the Data JSON-schema package's existing projection and compiler to realize `schemaFromGraph({root,schemas})` in src/contracts.mjs, exported through its existing contracts subpath. The argument contains exactly those two keys from L-OA02 (without the Systems kind/version wrapper); schemas is the flat list of exactly `{id,schema}` entries. The Data API admits a bounded canonical snapshot, verifies IDs, uniqueness, root membership and body correspondence, and returns a normal SchemaContract for root. Duplicate entries are invalid here; Systems normalizes repeated descriptor occurrences first. Input order is immaterial. This is a pure Data schema-construction operation, with no Systems imports, IO, filesystem roots or personal-authority semantics.

The resulting validators resolve only within that immutable explicit universe plus their own local/nested scopes. Reuse evaluatorSchemaGraph's actual house-address, relative-URI, nested-$id, local-fragment, tuple and dependency semantics and the existing compiler. No copied Systems $ref resolver, ambient registry lookup, remote schema fetch, delayed ambient completion or new validation engine is permitted. A required unresolved reference or invalid root compilation refuses graph construction. A locally self-referential root and mutually referring explicit definitions remain supported. Definitions in annotations/const/example data are not invented external dependencies by an indiscriminate string scan.

Every returned contract exposes its actual frozen schema and complete explicit transitive reference universe as SchemaContracts, with the same validate/assert/errors behavior as existing contracts. Referenced contracts retain their closed environment when used independently. A finite graph may use internal object cycles; all objects and reference arrays are frozen after construction. Serialization uses L-OA02's finite projection, not recursive JSON serialization of those runtime objects. Compile the root during construction so a missing required reference cannot be deferred until after private retention. The current compileJsonSchema API catches compilation failures and returns a validator reporting issues of kind schema; it does not throw those failures. Observe that failure carrier during construction (a null probe may inspect issue kinds), refusing a schema issue. An ordinary instance rejection of null is not a schema failure and must not reject an otherwise valid graph. Do not claim eager compilation succeeded merely because the compiler returned an object. Referenced roots may compile on their own first use against the same fixed universe; such evaluation must never consult or mutate the global declared registry.

schemaFromGraph neither registers nor reads process-global declared schemas. Existing schemaFrom retains its current open-mode API for unrelated callers during this transformation. Descriptor rehydration uses the closed API for marked and unmarked operations, eliminating descriptorContracts' process-global first-wins cache entirely. Do not add a new shared cache keyed only by $id. A local private immutable graph per descriptor is sufficient. An old descriptor missing a required definition must be regenerated from its actual source contract; a permissive fallback is not an accepted migration.

## L-OA05 — Resolve and retain one matching executable

lazyOperation takes a bounded canonical immutable snapshot of its complete serializable descriptor before exposing it for discovery. Construct domain/codomain from their explicit graphs. Validate admission eligibility and recompute personal schemaBindings immediately. Input mutations after this point must not change discovery, the expected contract or execution.

The family load is memoized per lazy operation, including failure, so concurrent first calls share one result. Among the loaded family require exactly one operation with the descriptor's verb. Before obtaining an execution result, compare that candidate's ref, verb, admission presence/value, schemaBindings presence/value, both complete normalized schema universes (including absence), input/output formats, effects, reads, writes, options and relation. Scalar/array fields use exact canonical equality; compare optional absence distinctly. Summary/description are descriptive and do not decide authority. Recompute the candidate's personal schema bindings from its actual graphs rather than trusting a copied field. A changed reference, dropped admission, extra same-verb candidate, conflicting schema, mismatched effect or closure refuses before calling any candidate executor.

Retain the exact verified candidate and executor after matching; do not search a mutable returned family again on each call. Subsequent family array mutation cannot swap the verified executable. Reject malformed candidates and thenable/accessor tricks at the serializable boundary. Executable closures remain trusted fabricated code whose source identity is separately bound; descriptor matching is not a sandbox for arbitrary host JavaScript. L-C10's restricted personal factory binding is required before loading a family, since checking after an unsafe factory ran would be too late. This specification does not license process-wide ports for a personal lazy factory.

## L-OA06 — Aliases, argument defaults and pure composition

operationAs retains admission, computed schemaBindings, schemas, boundary formats, effects, reads, writes, options, relation and any available SEN term/typed descriptors. The changed verb produces its proper new declaration reference and requires its own exact context permission/capability admission. A same-verb alias returns the original operation. Alias execution delegates only to the source operation's fixed executor; an alias cannot strip the personal requirement or borrow permission for another operation reference.

withOperationArguments preserves the original operation reference and complete contract, including lazy/SEN distinctions, while wrapping only the application of host argument defaults. It must not reconstruct a lazy SEN declaration as a new host declaration. Snapshot admissible default argument data; request argument precedence remains the existing behavior. Neither defaults nor arguments override the input's context, authenticated principal, prepared snapshot or scoped ports. Permission selection always uses the validated body and installed metadata.

The existing compose helper composes pure SEN terms; it does not compose two context/effect grants. If either operand carries personal admission, refuse that implicit composition before constructing a new operation, including when the two admission values happen to be equal. Two equal action names do not establish permission for a new operation reference, prove that an intermediate result preserves context, or authorize a second use. Personal workflows continue through explicitly admitted operation boundaries and their scoped ports. This rule preserves ordinary unmarked pure composition; it supplies no new composite grant language or hidden owner fallback. The composition report must expose this inability rather than reporting the pair as admissible based only on schema ID equality. Existing unmarked report fields retain their meaning; add `admissionCompatible` and include it in `ok`, and make composes return that resulting ok.
